1. The Deadlock (Phase 2):
In the `deadlock_simulation.py` script, explain step-by-step how the "Circular Wait" condition occurred between Model A and Model B.
:Model A first acquired GPU 0 and then tried to acquire
GPU 1.
At the same time, Model B first acquired GPU 1 and then
tried to acquire GPU 0.
Therefore, Model A was holding GPU 0 while waiting for
GPU 1, while Model B was holding GPU 1 while waiting
for GPU 0
Both models were waiting for a resource held by the other
model. This created a Circular Wait condition and caused
the system to freeze.

2. The Solution (Phase 3):
By changing the code in `deadlock_avoidance.py` so that Model B also requests GPU 0 first, how did this specifically break the "Circular Wait" condition? 
:The Circular Wait condition was broken by forcing Model B
to request GPU 0 before GPU 1, just like Model A.
Therefore, both models follow the same resource ordering:
GPU 0 --GPU 1
One model can acquire both GPUs and finish its work before
the other model gets the resources.
As a result, the threads no longer wait for each other
in a circular manner, so the Deadlock is avoided.
